# v0.8 设计：v0.7 功能踩实

日期：2026-10-30
状态：明细清单已经用户确认（A + B + C 全部纳入）

## 背景与目标

v0.7 交付了图片插入与 PDF 导出两个大功能，但真实场景覆盖不足：IME 清单停留在「待人工走查」，图片插入只验证了单张 PNG 的 happy path，PDF 导出只验证了基本公式文档。竞品调研的结论是用户离开这类编辑器多因「细节不稳」而非功能不够。因此 v0.8 不加新功能，专注把 v0.7 踩实。

## 范围

### A. IME 验证与修复

- A1 组合输入自动化：在网页回归与桌面 e2e 中加入 compositionstart/update/end 用例，覆盖：组合中不触发预览覆盖、组合结束后文本正确、组合中粘贴/导出被正确拦截。
- A2 Windows 真机走查 docs/ime-checklist.md（微软拼音、搜狗）。
- A3 Android 真机走查（Gboard、搜狗）。
- A4 修复走查发现的问题；走查表随交付整理为带具体操作步骤的清单。此项为弹性项，超出部分顺延，不阻塞发布。

### B. 图片插入踩实

- B1 多图粘贴/拖入：现状只插第一张（pickClipboardImage 返回首个匹配项），其余静默丢弃。改为全部插入：桌面逐张 writeImage 落盘，web/Android 逐个转 data URL；收集完成后一次 replace 插入，多图以空行分隔；个别失败跳过并汇总提示。
- B2 拖拽兜底：window 级 dragover/drop 对 Files 类型 preventDefault，防止图片拖到编辑器外（页面空白、窗口边缘）被浏览器直接打开替换整个页面；非编辑器区域的落点仅防替换并 toast 引导，不插入。
- B3 并发保护：新增 imageBusy（与 desktopBusy 分离，后者只管文件读写 IPC）；插入批次进行中再次粘贴/拖入 → toast「正在插入图片，请稍候」并忽略。
- B4 桌面 e2e：插入图片后 Ctrl+Z 撤回（markdown 恢复、无图片引用残留）。
- B5 桌面 e2e：失败文案三例——未保存文档 / 超 5MB / MIME 与魔数不符。

### C. PDF 导出踩实

- C1 缺图自动内嵌：exportBodyHTML 改为 async；桌面导出（HTML 与 PDF 共用管线）时对未加载的本地相对路径图片逐个走 readImage 桥接内嵌，读取失败保留「未嵌入」占位；web/Android 行为不变（本地图片仍占位）。本地文件读取无隐私顾虑，不再要求「先在编辑器中点加载」。
- C2 导出反馈：新增 exportBusy；导出期间 #status 显示「正在导出…」，完成/失败恢复；期间重复触发导出被忽略。
- C3 跨页目检：生成含超页代码块、长表格、长引用的样例导出 PDF，目检断行与表头表现；按需微调 PRINT_CSS。Chromium 对超高元素通常会自动忽略 break-inside:avoid，先目检再决定是否特判。
- C4 完成提示带路径：main.cjs 的 exportPdf 返回值补充 filepath（writeBinaryFile 已返回），前端 toast「已导出：<完整路径>」。

## 非目标（留给 v0.9+）

多标签、最近文件、设置面板（字体/字号/主题）、代码块复制按钮、图床、assets 子目录配置。

- 网页回归（tests/web）：新增 v08_test.py——多图 data URL 粘贴、composition 组合输入用例、拖拽兜底（合成 drop 到非编辑器区域，断言不发生导航）。
- 桌面 e2e（tests/desktop-e2e.cjs）：多图落盘、插入后撤销、失败文案三例、未加载图自动内嵌导出、导出状态与路径提示、长文档 PDF（C3 样例）。

- 人工：A2/A3 走查表执行（需用户配合真机）。

## 风险与对策

- exportBodyHTML 变 async：调用方 exportHTML/exportPDF 均已 async，补 await 即可，影响面小。
- Chromium print 分页行为与预期不符（C3）：以目检为准，预留 PRINT_CSS 微调。
- 多图一次性 replace 内容较长：与现有 replace 机制一致，无新风险。
- IME 走查发现问题数量不可预估：A4 弹性顺延。
