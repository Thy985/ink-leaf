# 双工作视图交互原型：验证范围

日期：2026-11-28
状态：原型 spec（配合 `2026-11-28-dual-view-architecture.md`，只验证交互，不进入实现）
原型位置：`.superpowers/prototypes/dual-view/index.html`（gitignore，不入库）

## 一、这版原型要验证什么

原型只有一个目的：在**不写生产代码**的前提下，把双视图最容易翻车的四处交互先做出来，让维护者能用眼睛判断方向，而不是靠文字争论。

| 编号 | 待验证决策 | 原型中的具体做法 |
| --- | --- | --- |
| D1 | 文档与 Agent 怎么共存 | 三态：仅文档（Agent 为可召回抽屉）、并排（固定分栏）、仅 Agent（文档变为可按需拉出的侧页）。给出显式切换，不隐藏入口 |
| D2 | 逐条确认在双视图下不退化 | 提案以「变更块」同时出现在文档正文与 Agent 面板摘要里，两处勾选状态同源；底部确认条显示 `已选 n/m`；不存在「全部采纳」单按钮 |
| D3 | Agent 跑工具时用户看到什么 | 工具轨迹条逐个步骤展示：动作、目标（文件夹/文档相对路径）、耗时、结果条数；首字延迟显示已等待秒数；`中断` 始终可点，中断后保留已完成的步骤与半成品 |
| D4 | 三个入口怎么收敛 | 左栏收敛为一个「定位」面板：一个搜索框 + 三个范围（工作区树 / 双链 / 最近），同一份结果列表换镜头，而不是三个并列面板 |

## 二、必须画出来的丑状态

1. 首字延迟（请求已发出、模型未回）
2. 工具调用失败（红色步骤 + 重试/跳过 + 回答降级说明）
3. 多步循环中途需要人确认（暂停在「将要新建 3 个文档」）
4. 空工作区（没有导入文件夹时的定位面板与 Agent 输入区）
5. 超长文件名（树、最近、引用 chip 三处截断策略）
6. 窄窗口（<900px 时分栏退化为抽屉 + 显式提示）

## 三、明确不做

- 不接 IPC、不调模型、不读写配置与真实文件；全部假数据，纯前端状态机
- 不改 `web/` 任何文件，不新增依赖，不引外部字体/图片/网络请求
- 不做第三阶段内容：任务持久化、历史成果库、多 Agent、MCP 编排
- 不定义提案的数据结构与落盘协议（那是 plan 的事），原型只演「人怎么看见与操作」
- 不做视觉定稿：颜色与字体现有取值直接复用，原型不引入新设计语言
