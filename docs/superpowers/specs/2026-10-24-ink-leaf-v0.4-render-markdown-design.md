# 墨页 v0.4：代码高亮与非跨块 Markdown 补齐

- 状态：Draft，待用户复核
- 日期：2026-10-24
- 范围：Web / Windows / Android 共享编辑器核心
- 相关代码：`web/model.js`、`web/renderer.js`、`web/app.js`、`web/styles.css`、`scripts/build-web.mjs`
- 相关测试：`web/model.test.js`、`tests/web/*.py`、`tests/desktop-e2e.cjs`、`tests/files.test.cjs`

## 1. 背景与现状

墨页当前是单文档、本地优先的 Markdown 编辑器，三端共用 `web/` 内的编辑器与渲染源码。现有实现有三个直接约束：

1. **逐块渲染**：`web/app.js` 把文档解析成块，`decorate()` 对表格、公式、HTML 等“富块”同时输出 `.block-source` 原文和 `.block-preview` 预览；普通段落走 `web/model.js` 的 `renderInline()`。跨块语法（脚注、链接引用定义）没有文档级上下文。
2. **代码块只有源码态**：`web/app.js:125-133` 对 `code` 块只输出 fence 和源码，`web/renderer.js` 没有 highlighter 依赖。
3. **消毒器严格**：`web/renderer.js:51-58` 禁止 `img`、`src`、`class`、`style` 和未知 URI；新增高亮不能靠放宽白名单解决。

README 已明确当前不含图片插入、代码语法高亮、完整 CommonMark/LaTeX；本次只处理“渲染深度”中的可离线、非跨块部分。

## 2. 目标

- 围栏代码块在非编辑状态显示语法高亮，点击后恢复原始 Markdown 源码编辑。
- 补齐不依赖文档级上下文的 Markdown 语法：Setext 标题、缩进代码块、裸 URL 自动链接、ATX 标题闭合井号。
- 保持 Markdown 原文 round-trip：打开、编辑、保存后的文本与输入一致（既有的 BOM/换行处理不变）。
- 三端共享同一实现，不新增原生 IPC、文件桥或网络依赖。
- 所有高亮资源离线打包，继续满足“文档不上传服务器”。

## 3. 非目标

- 图片插入与本地资源管理。
- 脚注、链接引用定义、定义列表等跨块语法；留到 v0.5。
- 完整 CommonMark/LaTeX 一致性；不改自研块模型为 markdown-it token 模型。
- 单元格级 WYSIWYG 表格、自动保存、PDF/打印、多标签/最近文件。
- 原生端代码改动、真机验收、CI、代码签名、自动升级。
- 完整 CommonMark 长尾（列表松紧、复杂嵌套、内联 HTML 等）。

## 4. 方案决策

采用**富块双态**，不采用编辑态实时高亮，也不采用整篇文档级渲染重写。

理由：

- 富块双态复用现有 `.rich-block`、`.block-source`、`.block-preview`、点击激活、选区恢复和撤销路径，不碰 IME/光标映射。
- 编辑态 token 化会重做光标、选区、组合输入和撤销，v0.4 风险不可接受。
- 整篇渲染会破坏逐块 keyed render 与块级撤销，属于 v0.5 的架构议题。

高亮器选择 `highlight.js` 的 common bundle：离线、自带 HTML 转义、语言别名成熟、BSD-3-Clause。`shiki` 的语法保真更好但体积和启动成本不适合当前 Electron/WebView；`Prism` 可行但不比 highlight.js 更省集成成本。

## 5. 架构与数据流

```text
Markdown 文本
  -> parseBlocks()                  web/model.js
       识别 setext / indented code / 原有块类型
  -> render() -> decorate()         web/app.js
       code 块走富块双态
  -> previewMarkdown(raw, type)     web/renderer.js
       markdown-it 渲染
       fence 规则（有语言且未超限）生成占位符 + 高亮片段；其余走默认转义
       DOMPurify 消毒
       回填高亮片段（二次白名单消毒）
  -> DOM
       inactive: .block-preview 高亮预览
       active:   .block-source 原始源码
```

块模型仍是唯一编辑真相；高亮只影响预览 DOM，不进入 `serialize()`。

## 6. 详细设计

### 6.1 代码高亮

#### 依赖与构建

- 在 `package.json` 增加 `highlight.js`（精确版本由 `package-lock.json` 固定）。
- `scripts/build-web.mjs` 的 `notice()` 列表加入 `highlight.js`，确保 `web/vendor/licenses.txt` 收集其上游许可；`licenses/third-party-original.txt` 同步补充。
- 不复制第三方主题 CSS；在 `web/styles.css` 内用 CSS 变量写浅色/深色 token 配色。
- `web/vendor/` 仍不纳入 Git；Android 通过 `npm run sync:android` 获得同一份资源。

#### 代码块进入富块双态

- `web/renderer.js` 的 `needsPreview()` 对 `code` 恒返回 `true`。
- `web/app.js` 的 `decorate()` 删除现有 code 专用分支，统一走富块分支：
  - `.block-source` 保存完整原文（含 fence 或缩进）。
  - `.block-preview` 在非激活态输出 `<pre><code>` 高亮结果。
- 点击 `.block-preview` 继续沿用 `web/app.js:654-665` 的激活逻辑，光标落在块首；进入源码态后 fence/缩进可见。
- 非激活时显示预览，激活时显示原文；与表格、公式、HTML 块一致。

#### 高亮规则

- 围栏代码块：取 info string 的第一个 token 作为语言名，例如 ` ```js title="x" ` 使用 `js`；其余 token 忽略。
- 语言名交给 `highlight.js` 的 `getLanguage()` 解析别名；未知语言、空语言、高亮抛错时回退为纯文本 `<pre><code>`，不弹 toast。
- 缩进代码块没有语言信息，按纯文本代码块显示。
- 单块高亮上限 `MAX_HIGHLIGHT_CHARS = 100_000` 字符；超限回退纯文本，避免 Android WebView 卡顿。常量放在 `web/renderer.js`。
- 不在源码视图（`#source` textarea）内做高亮；不对行内 code 做高亮。
- 不新增语言选择器或角标；代码工具栏按钮的 `title` 改为提示“在第一行反引号后输入语言名可高亮”。

#### 占位符与消毒

沿用 `web/renderer.js` 现有的公式占位符模式：

1. 覆盖 markdown-it 的 `fence` renderer，在 `env.codeFragments` 中保存高亮片段，渲染结果填入随机种子占位符（如 `INKCODE<uuid><n>END`）。
2. `DOMPurify.sanitize()` 使用现有配置，不放宽 `FORBID_TAGS` / `FORBID_ATTR`。
3. 消毒完成后回填占位符；回填前对高亮片段做二次消毒：只允许 `span` 和 `class`，并校验 class 以 `hljs-` 或 `hljs` 开头。
4. 占位符种子每次渲染重新生成；回填只替换本次种子。

这样用户 HTML 仍然不能带 `class`/`style`/`src`，高亮产生的 span 只在消毒后插入。

#### 激活态与失焦刷新

代码块在激活态不生成高亮预览，避免每次输入都同步跑高亮；`.block-source` 仍实时更新，保存与撤销不受影响。`decorate()` 通过 `block.id === activeId` 判断是否跳过高亮，跳过时给该节点标记 stale。离开该块（切换到其他块、编辑器失焦）时，对刚离开的代码块补一次高亮渲染；实现上在 `updateActive()` 记录 `lastActiveId`，仅当旧块是 code 且 stale 时重建该块预览。源码视图返回编辑前把 `activeId` 置空再 `render()`，确保预览不是激活态留下的纯文本。这样既避免输入路径的高亮开销，也不会留下过期预览。

#### 样式

- `.block-preview pre` 继承现有代码块视觉：等宽字体、浅色/深色背景、边框、圆角、`overflow-x: auto`。
- `.block-preview pre code` 不再重复内边距；避免 `.code` 容器与 `pre` 双重背景。
- 高亮 token 使用 `.hljs-keyword`、`.hljs-string`、`.hljs-comment`、`.hljs-number`、`.hljs-title`、`.hljs-attr` 等少量常用类；未覆盖的 token 继承正文色。
- 深色主题下重新定义 token 颜色，保持对比度；不引入外部主题。
- 393px 宽度下代码块只允许自身横向滚动，不产生页面横向溢出。

#### 失败与降级

- `highlight.js` 加载/执行异常不应导致整块渲染失败；捕获后输出转义纯文本。
- 超长代码只影响高亮，不影响编辑、保存和 Markdown round-trip。
- 高亮失败不写 localStorage、不发 toast，避免噪声。

### 6.2 Setext 标题

#### 解析

在 `web/model.js` 的 `parseBlocks()` 中识别：

```md
标题
====

二级标题
--------
```

- 下划线匹配 `^ {0,3}(=+|-+)[ \t]*$`，且前面至少有一行非空段落内容。
- 支持多行标题：连续段落行直到下划线，块 `raw` 保留全部行。
- `level`：`=` 为 1，`-` 为 2；块上增加 `style: 'setext'`。
- CommonMark 优先级：段落行后紧跟 `---` 时是 Setext H2，不是分割线；分割线需要前面有空行。
- 不改变 `classify()` 对单行的既有行为；Setext 识别放在 `parseBlocks()` 的段落消费路径。
- 块 ID 匹配继续走 `parseBlocks(text, previous)` 的 raw 匹配，不引入额外状态。

#### 渲染

- `decorate()` 对 `heading` 且 `style === 'setext'`：
  - 内容行走 `renderInline()`；
  - 下划线包进 `<span class="syntax setext-underline">`，非激活时隐藏，激活时可见。
- 如果标题因行内 HTML/实体触发 `needsPreview()` 的富块路径，`decorate()` 必须先拆出内容行与下划线：内容行单独交给 `previewMarkdown(content, 'paragraph')`，下划线只保留在 `.block-source`，不得进入 markdown-it 渲染。
- `updateUI()` 的大纲标签使用标题内容行（多行用空格连接），去掉行内标记与 ATX 前缀；不把下划线算进标签。
- ATX 标题路径保持不变。

#### 编辑交互

- 工具栏 H1/H2 作用于 Setext 标题时，保持 Setext 形态，只把下划线替换为 `===` 或 `---`；不转换成 ATX，避免多行标题被拆成多个标题。
- 在 Setext 标题内容行末尾按 Enter：把新段落插到下划线之后，保持标题完整；在其他位置按 Enter 沿用通用段落插入行为。
- 激活时显示下划线；非激活时下划线不可见但仍参与 `readBlock()` 的原文长度计算。
- 删除、合并、撤销继续走通用 `apply()`/`parseBlocks()`，不新增专用历史路径。

#### 测试重点

- 单行/多行 Setext 解析、level、raw round-trip。
- `段落\n---` 为 H2；`空行\n---` 为 HR。
- 大纲收录、H1/H2 下划线替换、标题末尾 Enter 行为。
- 含行内 HTML/实体的 Setext 标题走富块路径时，下划线不被当作 Markdown 渲染。
- 编辑后块 ID 稳定性。

### 6.3 缩进代码块

#### 解析

- 在 `parseBlocks()` 顶层位置识别：行首 4 个空格或 1 个 tab，且该位置是文档开头或前一行是空行。
- 该检测必须优先于列表、标题、表格等单行分类：顶层以 4 空格缩进的 `- item`、`# heading` 等按 CommonMark 属于代码，不是列表/标题。
- 消费后续空行和缩进行；块尾的空行不计入 `raw`，留给后续 blank 块。
- 块对象：`{ type: 'code', style: 'indented', raw }`，无 `info`。
- 列表内容中的缩进行由列表块优先消费，不在此路径识别；测试覆盖“列表项续行不被误判为代码”。
- 既有块模型不在空行后继续消费列表续行，因此“列表 + 空行 + 4 空格行”会按顶层缩进代码处理；这是已知边界，用测试锁定，不在 v0.4 扩展完整列表语义。

#### 渲染

- 走与 fenced code 相同的富块双态。
- `previewMarkdown()` 用 markdown-it 的缩进代码规则渲染为 `<pre><code>`；没有语言，不高亮。
- 激活时 `.block-source` 显示原始缩进；保存时保持原样。

#### 止损规则

如果缩进代码块与列表续行、块 ID 或选区恢复产生无法在模型测试中稳定覆盖的冲突，则**从 v0.4 移除该项，整体留到 v0.5**；不接受只完成一半或改变 round-trip 的实现。

### 6.4 裸 URL 自动链接

#### 非富块内联内容（段落、列表、引用）

在 `web/model.js` 的 `renderInline()` 增加 URL 识别：

- 只识别 `http://`、`https://`、`mailto:` 开头的 URL。
- 不识别 `www.` 前缀；不识别裸邮箱。
- 不进入行内 code，不在已有链接的 label 内二次链接化。
- 输出 `<a href="..." target="_blank" rel="noopener noreferrer">...</a>`，可见文本保持原文，`textContent` 仍是原 Markdown。
- 尾部标点 `. , ; : ! ?` 和不成对的 `)` 不纳入链接；成对括号保留在链接内。
- 只允许 `isSafeLinkTarget()` 认可的 scheme；`javascript:`、`data:` 不生成 `<a>`。

#### 富块

- `web/renderer.js` 的 markdown-it 实例启用 `linkify: true`，让表格、HTML、公式等富块中的裸 URL 也可点击。
- 同时设置 `md.linkify.set({ fuzzyLink: false, fuzzyEmail: false })`，只保留显式 `http://`、`https://`、`mailto:`，与 `renderInline()` 的识别范围一致；不因富块路径额外识别 `www.` 或裸邮箱。
- 现有 DOMPurify URI 白名单不变；普通点击不打开链接，Ctrl/Cmd+点击沿用 `web/app.js:678-682`。
- 两条路径的边界差异（尾部标点、括号）用测试锁定，不要求逐字符一致，但安全 scheme 与可见文本必须一致。

#### 测试重点

- URL 末尾的中英文标点、括号。
- 行内 code、链接 label 内不链接化。
- 不安全 scheme 不生成 `<a>`。
- 链接化后文本 round-trip 不变。

### 6.5 ATX 标题闭合井号

- `## 标题 ##` 的显示与大纲标签去掉尾部闭合井号；`raw` 保留。
- 激活时仍显示完整原文。
- `renderInline()` 的标题内容渲染和 `updateUI()` 大纲共用同一个 `headingLabel()` 辅助函数，避免两处规则漂移。

## 7. 安全

- 用户 HTML 继续经过现有 DOMPurify 配置；不新增 `img`、`src`、`style`、`class`、`data-*` 放行。
- 高亮片段只在主消毒后回填，并做 `span` + `class` 二次消毒；class 前缀校验。
- 语言名、info string 不进入 HTML 属性；只用于 `getLanguage()`。
- 不新增网络请求、不新增权限、不新增原生桥接。
- CSP 不变；高亮脚本随 `web/vendor/renderer.js` 打包。
- 新增 XSS 回归：代码内容含 `<script>`、`</code><img onerror>`、`javascript:` URL、`data:` URL。

## 8. 兼容性与回归

- 共享 `web/` 源码，Web/Windows/Android 同时生效；原生端只重新同步资源，无 Java/C# 改动。
- 所有代码块（含无语言 fence）进入富块双态，这是有意的行为变化；文档与测试同步更新。
- 无语言代码块仍可点击编辑原文；复制、粘贴、撤销、IME 组合输入路径不变。
- 现有表格、公式、HTML、任务列表、查找替换、大纲、主题、专注模式不受影响。
- 文件格式、大小限制、BOM/换行策略不变。
- 深色主题与 393px 移动布局纳入手工和自动化检查。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Setext/缩进代码改动 parser，破坏 round-trip 或 ID 稳定 | 先补模型测试；缩进代码设止损规则，必要时降级到 v0.5 |
| 所有代码块变富块，改变现有编辑行为 | 更新 smoke/advanced 测试与 README；手工检查点击、复制、撤销 |
| 高亮片段绕过消毒 | 占位符 + 主消毒 + 二次 span/class 白名单；XSS 用例 |
| highlight.js 体积/Android 启动变慢 | 先用 common bundle；若启动或包体回归明显，改为 core + 注册常用语言 |
| 大代码块阻塞渲染 | 100k 字符上限，超限纯文本；keyed render 只重绘变化块 |
| 深色主题 token 对比度不足 | 自定义配色并用截图/手工检查 |
| 无 CI，回归依赖手工 | 本批 PR 记录完整命令与结果；CI 作为发布收口独立项 |

## 12. 后续里程碑

- **v0.5：跨块 Markdown**。脚注、链接引用定义、定义列表；先做文档级上下文设计（引用表/两遍解析），再决定是否扩展块模型。
- **v0.6：表格编辑增强**。增删行列、列对齐、Tab 循环；不做单元格级 WYSIWYG。
- **单独立项：图片**。先定资源策略（data URL / 相对路径 / 旁挂目录），再动三端文件桥、渲染白名单与体积限制。
- **发布收口**：CI、Windows/Android 真机验收、签名、图标、SmartScreen/IME；公开分发前必须完成，但不与本功能批混在一起。

## 14. 验收样例

以下文档应能完整 round-trip，并满足对应显示行为：

````md
标题
====

二级标题
--------

普通段落，包含裸链接 https://example.com/path?q=1。

```js
const answer = 42;
console.log(answer);
```

    indented code
    second line

段落
---

```text
<code> 不执行，只显示
```
````

预期：

- 两个 Setext 标题进入大纲；`段落\n---` 是 H2，不是分割线。
- `js` 代码块非激活时高亮，点击后显示 fence 和原文。
- 缩进代码块作为代码块显示，保存后保留 4 空格缩进。
- 裸链接可 Ctrl/Cmd+点击；文本内容与保存结果不变。
- `text` 代码块内的 HTML 被转义显示，不执行。
