# 墨页 v0.7 设计：图片插入与 PDF 导出

日期：2026-10-30。范围：纯 P0 —— 桌面图片插入（粘贴 + 拖拽）、桌面 PDF 导出、IME 真机验证清单。版本目标 0.7.0。

## 背景

竞品与社区调研（V2EX / GitHub issues / Typora、MarkText、Obsidian、思源等）显示：图片工作流（粘贴/拖拽→自动落盘→相对路径）与 PDF 导出是证据最强的两个缺口；中文输入法真机验证是信任层空白。墨页 v0.6 已有图片"渲染"闭环（readImage 桥接 + 占位卡），但缺少"插入"入口。

## 非目标

- 图床 / PicGo 集成（引入外部网络依赖，违背隐私立场）。
- `assets/` 子目录与自定义图片目录配置（YAGNI，v0.7 固定文档同目录）。
- 多标签、最近文件、主题/字体自定义（调研 P1，留给 v0.8）。
- Web 端 window.print 导出、Android 图片插入（无任意文件写入权限）。

## 模块 1：图片插入（桌面完整实现）

### 数据流

1. 入口：`paste` 事件（`clipboardData.items` 含 `image/*`）或 `drop`（`dataTransfer.files` 含图片扩展名）。文本粘贴/拖放行为不变。
2. 前置条件：
   - 桌面且文档已保存（已知本地路径）→ 走落盘流程；
   - 桌面未保存 → 提示"先保存文档，再粘贴图片"（与 v0.6"未保存不解析本地图"立场一致，避免另存为后的目录竞态）；
   - Web（含 Android WebView）→ 剪贴板图片转 data URL 内嵌插入，单图 ≤2 MiB，超出明确拒绝。
3. 渲染层读取 `ArrayBuffer` → preload 新接口 `inkstone.writeImage(nameHint, bytes)` → 主进程。
4. 主进程 `desktop/files.cjs` 新增 `writeImageFile(baseDir, nameHint, bytes)`：
   - 目标目录 = 已保存文档的所在目录（主进程由当前文档路径决定，不接受渲染层传目录）；
   - 文件名 = `粘贴图片-YYYYMMDD-HHMMSS` + 冲突序号 + 扩展名；扩展名由 MIME 映射（png→.png、jpeg→.jpg、gif→.gif、webp→.webp、bmp→.bmp、avif→.avif），未知 MIME 拒绝；不使用用户可控的原始文件名；
   - 校验：大小 ≤5 MiB；文件头魔数与映射扩展名一致（反向复用 IMAGE_SIGNATURES）；目录必须存在；
   - 原子写：临时文件 + `rename`，失败保留原状并报错；
   - 返回生成的文件名。
5. 渲染层在光标处插入 `![粘贴图片](文件名)`，走既有 apply/history 管线，天然可撤销；渲染层随后经既有 readImage 桥接显示（v0.6 闭环，无新渲染逻辑）。

### 边界

- 拖拽：仅当 `files` 存在且桌面环境时 `preventDefault` 并处理；否则沿用浏览器默认。
- 导出 HTML / PDF：粘贴的图片即文档目录内的本地图，v0.6 导出规则自动覆盖。
- Web data URL 插入后，文档体积与 2 MiB 读取上限的关系由用户自行权衡；单图硬上限 2 MiB。

## 模块 2：PDF 导出（桌面）

1. 桌面菜单「文件 → 导出 PDF」→ `desktop:command exportPdf` → 渲染层 `exportPdf()`。
2. `exportPdf()`：`renderDocumentHTML(text(), {doc})`（MathML-only 公式、脚注锚点、data 图内嵌、缺图占位 —— 与导出 HTML 完全同一管线）+ 打印专用 CSS → `inkstone.exportPdf(html, suggestedName)`。
3. 主进程：`showSaveDialog`（扩展名白名单 `.pdf`）→ 隐藏 `BrowserWindow` 加载导出 HTML → `did-finish-load` 后 `webContents.printToPDF`（`printBackground: true`，默认边距）→ 原子写目标文件。
4. 失败（取消、写失败、printToPDF 报错）明确报错，不假称成功；不改动 Markdown 文档的已保存状态。
5. 打印 CSS：`@page` 边距、`pre` 防分页断裂、`img` max-width:100%、MathML 块不截断。

## 风险

- `printToPDF` 在无 GPU/无头环境的表现：桌面 e2e 直接用真实 printToPDF 验证。
- data URL 插入导致文档膨胀：单图 2 MiB 硬上限 + 文档内提示。
- Windows 文件名冲突：秒级时间戳 + 序号递增策略。
